# INTER-IIIT SPORTS MEET — FRONTEND UI SKILL

## ROLE

Act as a senior product designer and senior frontend engineer
working on a polished national-level sports event website.

The quality bar is comparable to a carefully designed modern
frontend product, not a generic AI-generated website.

You are responsible for:
- visual hierarchy
- art direction
- layout composition
- typography
- spacing
- color system
- interaction design
- motion
- responsive behavior
- accessibility
- component consistency
- visual polish

The website must feel intentionally designed.

It must NOT feel like:
- a generic Tailwind template
- an AI-generated website
- a generic SaaS landing page
- a university portal
- a dashboard
- a collection of identical cards
- an over-animated marketing page

The visual identity should communicate:

PRESTIGE
ENERGY
COMPETITION
YOUTH
NATIONAL SCALE
INSTITUTIONAL CREDIBILITY

============================================================
# CRITICAL EXISTING-PROJECT RULE
============================================================

THIS IS AN EXISTING WORKING APPLICATION.

The existing application is the source of truth for:
- routing
- page structure
- content
- data
- components
- asset architecture
- functionality

NEVER rebuild the project from scratch.

NEVER replace the existing architecture merely to improve UI.

NEVER remove working routes.

NEVER remove working functionality.

NEVER change JavaScript to TypeScript.

NEVER introduce a backend.

NEVER replace the existing asset architecture.

NEVER perform broad refactoring unless it is genuinely required
for the requested visual improvement.

Prefer:
- modifying existing components
- improving existing CSS/Tailwind classes
- improving layout composition
- extracting only genuinely reusable visual patterns

The objective is:

EXISTING FUNCTIONAL APPLICATION
        +
HIGH-END VISUAL REFINEMENT

NOT:

EXISTING APPLICATION
        ↓
COMPLETE REWRITE

============================================================
# DESIGN PHILOSOPHY
============================================================

The visual direction is primarily inspired by the Inter-IIIT /
ASMita event aesthetic and the supplied official brochure.

The website should feel like a modern evolution of that identity.

Do not imitate any external website literally.

Use original composition and implementation.

The design should combine:

Editorial sports-event identity
+
Modern frontend craftsmanship
+
Institutional credibility
+
Youthful athletic energy

The interface should have deliberate visual rhythm.

Avoid making every section follow:

heading
subtitle
three cards
three cards
footer

Variation is essential.

Use:
- editorial layouts
- feature sections
- large typography
- image-led blocks
- statistics
- asymmetric layouts
- full-width bands
- compact information blocks
- visual separators
- strong section transitions
- intentional whitespace

============================================================
# COLOR SYSTEM
============================================================

THIS IS A HIGH-PRIORITY REQUIREMENT.

The current implementation is too green-heavy.

REDUCE GREEN AS A SURFACE COLOR.

Green is the BRAND / PRIMARY ACCENT.

It should NOT dominate every section.

The overall interface should instead be based on:

WARM IVORY / PALE YELLOW
+
GREEN
+
GOLD
+
YELLOW
+
DARK TEXT

------------------------------------------------------------
PRIMARY SURFACE
------------------------------------------------------------

Use a VERY LIGHT warm yellow / ivory / cream as the dominant
page background.

It should visually feel like:

warm paper
soft ivory
subtle golden-white
premium cream

It should NOT look:
- pure white
- grey
- beige-heavy
- saturated yellow

The tint should be subtle.

------------------------------------------------------------
GREEN
------------------------------------------------------------

Green represents:
- Inter-IIIT identity
- important headings
- brand elements
- selected section backgrounds
- active states
- important accents

Green should be used intentionally.

Do NOT make every section green.

Do NOT tint every image green.

Do NOT place green overlays over normal photography by default.

------------------------------------------------------------
YELLOW
------------------------------------------------------------

Yellow is an energetic accent.

Use it for:
- hero accents
- navbar accents
- CTA highlights
- active indicators
- decorative shapes
- small labels
- event markers

Yellow should provide energy without becoming visually noisy.

------------------------------------------------------------
GOLD
------------------------------------------------------------

Gold should communicate:
- premium
- achievement
- championship
- awards
- important metadata

Use subtly.

------------------------------------------------------------
TEXT
------------------------------------------------------------

Use dark green / near-black / deep charcoal where appropriate.

Text must have strong contrast.

Do not use low-contrast light green text on pale ivory.

============================================================
# IMAGE TREATMENT
============================================================

THIS IS ANOTHER HIGH-PRIORITY REQUIREMENT.

The existing implementation applies too much green tint to
event imagery.

REMOVE UNNECESSARY GREEN IMAGE OVERLAYS.

Normal images should look like normal images.

Do NOT apply a green overlay to every event card.

If image treatment is necessary, use:
- subtle dark overlay for text readability
- soft gradient near text
- restrained contrast
- natural image colors

Do NOT:
- colorize all images green
- apply heavy opacity overlays
- reduce image clarity
- make photographs look like green posters

Images should remain visually rich.

Use the local asset architecture already present in:

/public/assets/

Do not change it unnecessarily.

============================================================
# TYPOGRAPHY
============================================================

Typography is a major visual component.

Create a clear hierarchy:

EVENT LABEL
↓
DISPLAY HEADING
↓
SECTION HEADING
↓
SUBHEADING
↓
BODY
↓
METADATA

Major headings should feel athletic/editorial.

Use strong display typography for:
- hero
- major section headings
- important statistics

Body typography must remain highly readable.

Do not use oversized typography everywhere.

Do not overuse uppercase text.

Use letter spacing intentionally.

# EVENTS

Use a combination of:
- image-led cards

============================================================
# IIIT LOGOS
============================================================

Prefer:
- clean logo tiles
- consistent dimensions
- subtle borders
- ivory surface
- green/gold accents
- restrained hover treatment

Make the section feel like a national participation showcase.

============================================================
# GALLERY
============================================================

Gallery should feel editorial.

Avoid a generic 3-column image grid.

Use:
- varied image sizes
- masonry-like composition where practical
- featured image
- carousel
- hover interaction
- subtle captions if useful

Keep it lightweight.

Do not over-engineer.

============================================================
# SPONSORS
============================================================

Sponsors should feel premium and trustworthy.

Avoid giant generic cards.

Use:
- clean logo presentation
- subtle gold/green accents
- balanced spacing
- consistent logo sizing

============================================================
# CONTACT
============================================================

The Contact page currently has visibility/readability problems.

This is an explicit correction.

Contact information must be immediately readable.

Ensure:
- heading has strong contrast
- contact labels are visible
- body text is readable
- icons do not overpower content
- phone/email/address information is clearly separated
- no text disappears into the background
- no low-contrast green-on-ivory combinations

Use clear visual grouping.

The page should feel like a professional event contact page,
not a decorative section where the actual contact information
gets lost.

============================================================
# CARDS
============================================================

Do not use:

white background
+
large border radius
+
large shadow
+
icon
+
heading

for everything.

That is a common AI-generated visual pattern.

Instead use different visual treatments:

- flat editorial blocks
- image-first cards
- bordered cards
- accent cards
- large feature blocks
- compact information cards

Use shadows sparingly.

Use radius consistently but not excessively.

============================================================
# BORDERS AND SHAPES
============================================================

Use borders and decorative geometry intentionally.

Possible elements:
- thin gold rules
- green accent lines
- yellow geometric shapes
- oversized typography
- subtle curves
- diagonal section transitions
- corner accents

Do not decorate every section.

Decorative elements should reinforce the sports/event identity.

============================================================
# MOTION SYSTEM
============================================================

Use motion, but keep it professional.

Motion should feel:
FAST
SMOOTH
INTENTIONAL

Use subtle:
- hero entrance
- staggered text reveal
- section reveal
- image hover scale
- card hover movement
- navigation indicator transition
- carousel transition
- number count-up
- subtle marquee/ticker

Recommended general interaction range:

150–600ms

Use easing that feels natural.

Avoid:
- excessive bounce
- continuous floating
- excessive parallax
- long cinematic transitions
- animation on every element
- distracting background animation

Animation must never interfere with usability.

Respect reduced-motion preferences when practical.

============================================================
# INTERACTION QUALITY
============================================================

Every interactive element should communicate state.

Buttons:
- hover
- active
- focus

Navigation:
- active route
- hover
- mobile state

Cards:
- subtle hover
- clear clickability where applicable

Gallery:
- clear controls
- smooth transitions

Forms:
- visible focus state
- clear feedback

Do not create fake interactions merely for visual effect.

============================================================
# RESPONSIVE DESIGN
============================================================

Treat mobile as a designed experience.

Do not simply stack the desktop layout.

Check:
- hero
- navbar
- typography
- event cards
- IIIT logo grid
- statistics
- gallery
- contact information
- footer

At mobile widths:
- reduce decorative complexity
- preserve hierarchy
- maintain comfortable spacing
- avoid horizontal overflow
- keep important information above the fold where practical

============================================================
# ACCESSIBILITY
============================================================

Maintain:
- readable contrast
- semantic HTML
- alt text for meaningful images
- keyboard focus states
- usable button sizes
- accessible navigation
- reduced-motion compatibility where practical

Do not sacrifice accessibility for visual effects.

============================================================
# CODE QUALITY
============================================================

Use the existing Next.js + JavaScript + Tailwind architecture.

Prefer:
- reusable components
- data-driven rendering
- existing utilities
- existing asset paths

Avoid:
- unnecessary packages
- unnecessary state libraries
- giant components
- duplicated markup
- excessive abstraction
- rewriting working code

============================================================
# HARD SAFETY RULE
============================================================

IF A VISUAL CHANGE CAN BE ACHIEVED WITHOUT CHANGING STRUCTURE,
PREFER THAT APPROACH.

Do not rewrite routing.

Do not delete components.

Do not rename asset files unnecessarily.

Do not change data unnecessarily.

Do not remove content.

Do not change functionality.

Do not replace working pages.

Do not introduce a new framework.

Do not migrate the project.

The current implementation is valuable.

Improve it.
